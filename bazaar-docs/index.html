Chapter 01

Platform Overview & Core Architectural Paradigm

1.1 Executive System Topology

BazarBoost is a production-deployed, enterprise-scale multi-vendor e-commerce ecosystem built on a tightly integrated full-stack JavaScript monorepo. The platform enables independent vendors to open storefronts, list products, engage in real-time price negotiations with shoppers, and access micro-financing capital instruments — all within a unified, multi-tenant-aware infrastructure.

The system is designed around three foundational architectural principles:

  1. Tenant Isolation by Design — Every database query, socket room, and API response is scoped to the authenticated user's storeId or userId. Cross-tenant data leakage is structurally impossible within the query layer.
  2. Event-Driven State Propagation — All critical financial state transitions (order completions, loan disbursements, discount activations) are processed through atomic, transaction-wrapped database operations and broadcast via Socket.io room emissions.
  3. Decoupled Service Boundaries — The frontend (Next.js), the API layer (Express), the real-time engine (Socket.io), and the background job processor (BullMQ) operate as logically separate services with well-defined, typed interfaces.

1.2.5 Middleware Pipeline

File: src/middleware/auth.js 
export const protect = async (req, res, next) => {
  // Stage 1 — Token Extraction & Verification
  const token = req.headers.authorization?.split(' ')[1];
  if (!token) return res.status(401).json({ message: 'No token provided' });

  const decoded = jwt.verify(token, process.env.JWT_SECRET);
  const user    = await User.findById(decoded.id).select('-password');
  req.user      = user;

  // Stage 2 — Admin Session IP Lock Guard
  if (req.user.role === 'admin') {
    const ipAddress = req.headers['x-forwarded-for'] 
                   || req.socket.remoteAddress || '';
    const session = await AdminSession.findOne({
      adminId: req.user._id, token
    });
    if (!session || session.ipAddress !== ipAddress) {
      return res.status(401).json({ message: 'Session invalid or expired' });
    }
  }

  // Stage 3 — Account Suspension Enforcement
  if (req.user.status !== 'active') {
    return res.status(401).json({ message: 'Account suspended' });
  }

  next();
};

Chapter 02

Calendar-Month Bounded Loyalty Discount Engine

2.1 System Overview

The BazarBoost Loyalty Discount Engine implements a rolling, calendar-month-bounded spend accumulation model that dynamically grants shopper discount tiers across all vendor storefronts. The engine is fully decoupled from individual vendor accounting — merchants always receive their full contracted payout, while the platform absorbs the discount subsidy from its commission pool.

2.1.1 Engine Architecture Flow

SHOPPER CHECKOUT PIPELINE
│
├─ [1] Cart Subtotal Computed
│       ↓
├─ [2] verify_monthly_loyalty_tier (Middleware)
│       ├── READ  LoyaltyLedgerCache { userId, monthKey }
│       ├── READ  LoyaltyConfig      (silverThreshold, goldThreshold)
│       └── RETURN tier ∈ { 'Standard', 'Silver', 'Gold' }
│               ↓
├─ [3] Local Vendor Coupon Applied First
│       (if coupon code present & valid)
│               ↓
├─ [4] Platform Tier Discount Stacked Second
│       ├── Silver → -5%  of post-coupon subtotal
│       └── Gold   → -10% of post-coupon subtotal
│               ↓
├─ [5] Order Created in DB
│       ├── platformCommission  = originalSubtotal × commissionRate
│       ├── loyaltyDiscount     = tierDiscountAmount
│       └── loyaltyTier         = 'Silver' | 'Gold'
│               ↓
├─ [6] Ledger Updated
│       └── LoyaltyLedgerCache.accumulatedSpend += orderTotal
│               ↓
└─ [7] Vendor Payout = totalAmount - platformCommission
        (loyaltyDiscount absorbed by platform, NOT deducted from vendor)

2.2.1 Month Key Generation

The loyalty ledger uses a composite month key to namespace each shopper's accumulator to a specific calendar month:

Composite Month Key Logic 
const getMonthKey = () => {
  const now = new Date();
  const yyyy = now.getUTCFullYear();
  const mm   = String(now.getUTCMonth() + 1).padStart(2, '0');
  return `${yyyy}-${mm}`;
};

Chapter 03

Escrow-Locked Inventory Micro-Financing Ledger

3.1 System Overview

The BazarBoost Micro-Financing Ledger provides capital access instruments for vendors who need operational liquidity. Vendors can apply for short-term escrow loans disbursed directly to their store wallet. Repayment is automated through a non-optional sweep mechanism that intercepts a percentage slice from every incoming order payout until the loan balance reaches zero.

3.4 Automated Repayment Hook

File: src/routes/orders.js (Interception Hook) 
const activeLoan = await VendorLoan.findOne({
  storeId,
  status: 'approved',
}).sort({ createdAt: 1 });

if (activeLoan) {
  const vendorGross = order.totalAmount - order.platformCommission;
  const repaymentSlice = Math.min(vendorGross, activeLoan.repaymentAmount);
  const netPayout = vendorGross - repaymentSlice;

  const session = await mongoose.startSession();
  session.startTransaction();
  try {
    const isFullyRepaid = repaymentSlice >= activeLoan.repaymentAmount;
    await VendorLoan.findByIdAndUpdate(activeLoan._id, 
      isFullyRepaid ? { status: 'repaid', repaidAt: new Date() }
                    : { $inc: { repaymentAmount: -repaymentSlice } },
      { session }
    );
    await Store.findByIdAndUpdate(storeId, {
      $inc: { 'wallet.balancePKR': netPayout },
      $push: { 'wallet.transactions': [
        { type: 'deposit', amount: vendorGross, reference: order._id },
        { type: 'loan_repayment', amount: -repaymentSlice, reference: activeLoan._id }
      ]}
    }, { session });
    await session.commitTransaction();
  } catch (err) {
    await session.abortTransaction();
    throw err;
  }
}

5.2 AI Dispute Arbitrator Pipeline

Using a lightweight transformer model (CLIP-ViT-B-32) loaded inside a background worker, BazarBoost scores dispute screenshots against the product catalog index to automate returns validation:

File: src/services/disputeAI.js 
import { pipeline } from '@xenova/transformers';

export const computeDisputeSimilarity = async (evidenceImagePath, catalogImageUrl) => {
  const encoder = await pipeline('feature-extraction', 'Xenova/clip-vit-base-patch32');

  const [evidenceEmbedding, catalogEmbedding] = await Promise.all([
    encoder(evidenceImagePath, { pooling: 'mean', normalize: true }),
    encoder(catalogImageUrl,   { pooling: 'mean', normalize: true }),
  ]);

  const dotProduct = evidenceEmbedding.data.reduce(
    (sum, val, idx) => sum + val * catalogEmbedding.data[idx], 0
  );
  return dotProduct;
};
✓

Similarity Threshold Matrix:

  • > 0.85: Auto-Reject dispute (Item matches listing image).
  • < 0.60: Auto-Approve refund (Definitive item mismatch).
  • 0.60 to 0.85: Escalate to manual human review queue.
